## 4. 写故事的规则（系列 DNA）

1. **流程**：先给 2-5 个候选（各带"内核一句话+暗线+梗概+互动点"）→ 用户选定 → 写全文 `故事文字稿.md` → **用户审稿**（一定会改，通常 1-3 轮）→ 定稿后才写代码
2. **篇幅**：约 7 节 + 尾声，全文 700-900 字。宁短勿长
3. **痛点只写一句**，绝不展开；全程不提"工作/领导/考核"等现实词（用隐喻承载）
4. **绝对不说教**：安慰靠画面、动作和时间本身；金句从角色口中自然说出或由物件承载（台账、妈妈的话、复印机）；删除一切"作者解说"式括号和劝告式祈使句
5. **软幽默**每篇 2-3 处（尼克的冷幽默最佳）
6. **系列母题**（可呼应不必全用）：甜的那半（大的/甜的给她）、尾巴盖膝盖、灯（总有窗亮着→站台灯→替你看天气的灯→专注的台灯）、慢的东西可靠、伞
7. **尾声两行**，纯画面词汇，收在温柔处；结尾固定寄语：
   `送给亲爱的 Lin` / `—— 永远站在你这边的 Zhe`
8. **无现实锚点**：不写年份日期，暴雨就只是暴雨

- 配角先例：老山羊（卖汁/修鞋）、老犰狳（预报员）、小鹿珍（同期同事，名字是"珍"，称呼是"小鹿"）、牛局长（只用剪影+双角）

**调色**：夜靛蓝系 #12161f-#232a47、奶白 #ece5d3、暖琥珀 #f4b860/#ffd98a。尾声幕用夜→暖的渐变，文字压深棕 #4a392b（对比度已调过，别再用 #5d4c3d 以下的浅色）

**布局铁律**：
- 每页 = 封面 + 若干编号场景（壹贰叁…kicker）+ 互动 finale + 尾声 + footer
- **正文场景一律"文字在上、插画跟随其后"的文档流布局**（`.flowtop` 模式）——绝对定位插画+margin 下压文字的旧写法在小屏会重叠，已全部废弃
- 封面例外：插画沉底、标题居上（`justify-content:flex-end`，已验证安全）
- 每页必备：左上 `◂ 书房` 返回链、封面徽记"动物城睡前故事 · 第 N 夜"、尾声后的"下一夜，正在来的路上"卡片、footer"第 N 夜 · 完"（这些直接从旧页复制）
- 字体：正文 sans（PingFang/雅黑 light）、标题与尾声 serif（Songti 系）

**SVG 纪律**（血泪教训）：
- 不要对 SVG 内 `<g>` 用 CSS transform（旋转原点是 viewBox 原点，会甩出画板撑爆布局）——动效用 opacity 过渡或 HTML DOM 元素做
- SVG `<text>` 必须算宽度，别超出书本/纸面形状
- 微信里 div transform 安全（翻页、泡泡都是 HTML）

## 6. 共享引擎 ZStory（assets/story.js）

`ZStory.init({storyId, audio:{...}, finale:{...}, weather:"rain"|"snow"})`
- 滚动浮现（IntersectionObserver 加 .in）、天气画布（`data-rain="a>b"` 属性控制密度，支持雨/雪）、点灯 finale、阅读标记（页脚出现即写 `localStorage zs_read_<id>`，书房据此亮灯）
- **钢琴 BGM**：`audio:{tempo, delayTime, feedback, wetness, style, chords:[{bass,notes[],spark[]}]}`（频率写实际 Hz）
- **四种演奏风格** `style`：
  - `lullaby`（默认）：低音铺底、音符依次落下
  - `sway`：低音后荡开，像车轮/摇篮（火车）
  - `bright`：轻快短琶音+勤快的高音星（喜剧/俏皮）
  - `sparse`：近乎齐奏的长音（最深摇篮曲）
- **调性分配**（保持互不相同）：书房 A、雨 E、火车 G、天气 D、彩排 C、晚安 F、偏心 B♭。新故事从剩下的调里选（如 A♭/B/E♭/F♯…），并让和弦进行走出 I–vi–IV–V 的同质家族（可用 ii、属七、小调开头等）
- 自动播放处理：页面加载即尝试 → WeixinJSBridgeReady → 首次触摸兜底；左下角"声音"钮开关；后台自动 suspend

## 7. 首页"故事小街"与如何加新故事

首页由 JS 生成：每个故事一座小房子（两座一行）。**奇数个故事 → 末行=新故事+虚线敬请期待房；偶数 → 虚线房+小树**——任何数量每行都是满的。屋顶小家伙固定在第一座房上。

**加第七夜（例如）的完整步骤**：
1. `missing/故事文字稿.md` 已有修订版《缺了一角》→ 请用户终审
2. 复制某个近期的夜（推荐 `/goodnight/` 或 `/evidence/`）作为模板 → 新文件夹如 `/missing/`（或按题意取名）
3. 改：场景文字与插画、`ZStory.init` 的 `storyId` 和 `audio`（新调性+风格）、封面徽记"第七夜"、footer"第 七 夜 · 完"
4. 互动 finale 自写在本页 `<script>` 里（惯例：**亲手把坏的变好**，终态浮现尾声两行，参考已有六种）
5. 首页 `index.html`：`STORIES` 数组加一行 `{id,url}`，`MOTIF` 加该夜的窗内小图标（cream 色简笔）
6. 按 §9 QA → push → 线上验证

## 8. 互动 finale 惯例

- 提示语"点一点…"（amber 高亮呼吸）
- 完成终态：改动定格 + 尾声两行浮现（`.lines p.on span` 模式）+ 提示语换成收束语（"到站了。/晴了。/剧终。/晚安。"）
- 调试参数：`?stage=final` 直达终态（每页自实现）

## 9. QA 清单（push 前必须全过）

1. **截图一律用真实 390 视口**：`--window-size=390,844` 且**不加** `--force-device-scale-factor`（DSF=2 会按 466px 排版，产生假溢出/假修复——本项目最大检查坑）
2. 逐幕截图：封面、每节、finale 初态+终态；检查文字重叠、图像是否越界、画风是否与已有夜一致
3. 控制台零报错：`--enable-logging=stderr` 过滤 CONSOLE/uncaught
4. 调试参数：`?static=1`（全浮现）`&only=sN`（单幕）`&stage=final`（终态）`&lit=all`（第一夜点灯）
5. 无头 Edge 坑：每次截图独立 `--user-data-dir`，偶尔静默失败→重试；加 `--no-sandbox` 更稳
6. 图像分析工具（如用）有假阳/假阴，关键结论用像素扫描佐证（PowerShell System.Drawing 按色带计数）
